# Coding rules

These rules apply to every coding task. Read them at the start of any session involving code.

## 1. Plan before code

Before touching any file, write the plan and get confirmation. If something goes wrong mid-task, stop immediately and replan — never push through.

## 2. Subagents for hard problems

Offload complex research, analysis, or multi-file investigation to subagents. This keeps the main context clean and throws more compute at the problem.

## 3. Self-improvement loop

Every lesson learned — a bug pattern, a wrong assumption, a better approach — goes into `tasks/lessons.md`. Read it at the start of relevant tasks.

## 4. Done means verified

Never mark a task complete without running tests and checking logs. Ask: would a staff engineer approve this? If not, keep going.

## 5. Bugs: just fix them

No hand-holding. Go straight to the logs, find the root cause, solve it.
